# Fit Model Phase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every job email shows a fit score from a model that retrains daily on the user's Gmail stars (good) and deletes (bad), and never blocks a job.

**Architecture:** A pure-Python logistic regression over binary word and two-word features of title plus description, in a new `fit.py`. Lessons and the trained weights live in Supabase. The 10-minute run loads the weights once and scores each job it emails. The daily heartbeat reads reactions over IMAP (read-only), saves them as lessons, retrains and reports agreement.

**Tech Stack:** Python 3.12, requests (PostgREST), imaplib, pytest. No new dependencies.

**Spec:** docs/superpowers/specs/2026-11-06-fit-model-design.md

## Global Constraints

- The model never blocks, holds back or reorders a job in phase 1.
- Gmail access is read-only (`select(..., readonly=True)`); nothing is written to Gmail.
- The stored model stays well under 1 MB (top 5,000 terms by absolute weight).
- With fewer than 20 good or fewer than 20 bad lessons, the email shows "Fit: learning, no score yet".
- Starting lessons leave out AI engineer titles and any job rejected for years, location, sponsorship, senior with no years, or no description.
- Comments are terse, commits are short lowercase messages, nothing is pushed without passing tests.

## Review Focus

- A starred email that is also in Trash: trash wins (the user deleted it after starring). Test in Task 3.
- A reaction on an old email with no job header: ignored, not an error. Test in Task 3.
- A job with an empty description: scored from the title only, and the Fit row says "(title only)". Test in Task 1.
- A missing or corrupt model row: the run still emails jobs with "no score yet". Test in Task 2.
- A description that is very long (50k+ chars): feature extraction stays bounded (first 20,000 chars). Test in Task 1.

### Task 1: The model

**Files:**
- Create: `fit.py`
- Test: `tests/test_fit.py`

**Interfaces:**
- Produces:
  - `features(title: str, text: str) -> set[str]`: lowercased tokens `[a-z][a-z0-9+#]*`, unigrams and bigrams. Title tokens are also added with a `t:` prefix. Only the first 20,000 chars of text are used.
  - `train(lessons: list[tuple[str, str, int]]) -> dict | None`: each lesson is (title, text, label with +1 or -1). Returns `{"w": {term: float}, "b": float, "good": int, "bad": int}`, or `None` when good < 20 or bad < 20. L2-regularised logistic regression by batch gradient descent: 300 epochs, learning rate 0.5, L2 1e-3, terms seen in at least 2 lessons. Keeps the top 5,000 terms by absolute weight.
  - `score(model: dict | None, title: str, text: str) -> float | None`: sigmoid of b plus the sum of weights for present features. None when the model is None.
  - `label(model, title, text) -> str`: the Fit row text, for example "82% (learned from 312 reactions)", "82% (title only, learned from 312 reactions)", or "learning, no score yet".

- [ ] **Step 1: Write failing tests** in `tests/test_fit.py`
  - `test_features_title_prefix_and_bigrams`: `features("Data Analyst", "SQL and Power BI")` contains `"t:data"`, `"data analyst"`, `"power bi"`, `"sql"`.
  - `test_long_text_is_cut`: `features("x", "a " * 60000)` returns in under a second, and the set size is under 10.
  - `test_train_needs_twenty_each`: 19 good plus 30 bad gives `None`.
  - `test_learns_separable_words`: 30 good lessons containing "power bi dashboards" and 30 bad containing "phd physics research" give `score(...)` above 0.8 for a new "power bi" text and below 0.2 for a new "phd physics" text.
  - `test_model_is_small`: training on 60 lessons of 400 random words each gives `len(model["w"]) <= 5000` and `len(json.dumps(model)) < 1_000_000`.
  - `test_label_texts`: `label(None, "t", "x") == "learning, no score yet"`; an empty text includes "title only".
- [ ] **Step 2:** `python -m pytest tests/test_fit.py -q`. Expected: FAIL (no module fit).
- [ ] **Step 3:** Implement `fit.py` with the four functions above.
- [ ] **Step 4:** `python -m pytest -q`. Expected: all pass.
- [ ] **Step 5:** Commit `"fit model from stars and deletes"`.

### Task 3: Learn daily from stars and deletes

**Files:**
- Modify: `mail.py`, `db.py`, `main.py` (`heartbeat`), `schema.sql`
- Test: `tests/test_main.py`, `tests/test_mail.py`

**Interfaces:**
- Consumes: Task 1 `train`, `score`; Task 2 columns and header.
- Produces:
  - Table `lessons (id bigint identity primary key, company_id bigint references companies on delete cascade, external_job_id text not null, title text, description text, label smallint not null, source text not null, fit real, created_at timestamptz default now(), unique (company_id, external_job_id))`, with row-level security on.
  - `mail.reactions(days=30) -> dict[str, int]`: maps job key to +1 (starred, in All Mail) or -1 (in `[Gmail]/Trash`). Trash wins. Only messages with an `X-Lookout-Job` header count. Read-only.
  - `db.save_lessons(rows)`: upserts on (company_id, external_job_id), so a newer label replaces an older one. `db.lessons() -> list[dict]`. `db.emailed(keys) -> dict[key, row]`: seen_jobs rows for those keys, with title, description and fit. `db.save_model(model, agreement)`.
  - `main.learn() -> str`: reads reactions, saves lessons (label, title and description from seen_jobs, fit at send time, source "star" or "trash"), retrains on all lessons, saves the model, and returns the agreement line: "Fit agreed with you on X of Y reactions today, A of B over the last 50". A lesson agrees when fit ≥ 0.5 and it's good, or fit < 0.5 and it's bad. Lessons without a stored fit don't count.
  - `heartbeat()` adds the `learn()` line to the daily summary. It's wrapped so a Gmail or training failure leaves the summary unaffected.

- [ ] **Step 1:** Apply the lessons DDL through psycopg, plus `schema.sql`.
- [ ] **Step 2: Failing tests**
  - `test_reactions_trash_wins_and_ignores_unkeyed` (test_mail): with a fake IMAP returning one starred and trashed key "1:a", one starred key "1:b", and one unkeyed message, the result is `{"1:a": -1, "1:b": 1}`.
  - `test_learn_saves_lessons_and_reports_agreement` (test_main): with reactions `{"1:a": 1, "1:b": -1}`, seen rows with fits 0.9 and 0.8, and 25 good plus 25 bad existing lessons, the saved lessons have labels 1 and -1, a model is saved, and the returned line starts "Fit agreed with you on 1 of 2 reactions today".
  - `test_heartbeat_survives_learn_failure`: with `learn` raising, the heartbeat summary is still sent.
- [ ] **Step 3:** Implement.
- [ ] **Step 4:** `python -m pytest -q`. Expected: all pass.
